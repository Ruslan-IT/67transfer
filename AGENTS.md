# Laravel Project Guidelines

## Язык общения

- Всегда отвечай пользователю на русском языке.
- Все объяснения, рекомендации и сообщения о выполненных действиях пиши на русском языке.
- Если пользователь пишет на русском языке, не переходи на английский без необходимости.
- Технические названия Laravel, PHP, библиотек, методов, классов и команд можно оставлять на английском.
- Сообщения об ошибках и названия команд показывай в оригинальном виде, но объясняй их причину на русском языке.

## Общий принцип работы

- Перед изменением файлов кратко объясни пользователю, что именно собираешься изменить.
- Сначала анализируй существующий код и структуру проекта.
- Не переписывай рабочий код без необходимости.
- Не меняй архитектуру проекта без явной необходимости.
- Сохраняй существующую архитектуру, соглашения об именовании и структуру каталогов.
- При исправлении ошибки сначала найди причину ошибки, а затем внеси минимальное необходимое изменение.
- Не создавай новые файлы, если задачу можно корректно решить изменением существующих файлов.
- Не удаляй существующий код, если он может использоваться другими частями проекта.
- Не изменяй несколько файлов без необходимости.
- После изменений проверяй, что код не содержит очевидных синтаксических или логических ошибок.

## Laravel

- Используй стандартные возможности Laravel, если они подходят для задачи.
- Соблюдай существующую структуру Laravel-приложения.
- Используй Blade для представлений.
- Не используй Vue, если пользователь явно этого не попросил.
- Не используй React, если пользователь явно этого не попросил.
- Не используй Inertia, если пользователь явно этого не попросил.
- Не используй Tailwind CSS.
- Для стилизации используй обычный CSS.
- Используй Laravel routes, controllers, models, services, requests и resources в соответствии с существующей архитектурой проекта.
- Не помещай сложную бизнес-логику непосредственно в Blade-шаблоны.
- Не помещай сложную бизнес-логику непосредственно в контроллеры, если для неё уже используется Service или другая подходящая архитектура.
- Используй Eloquent и существующие модели проекта.
- Не создавай дублирующую логику, если необходимая функциональность уже существует.
- Перед созданием нового Service, Repository, Trait или Helper проверь, нет ли уже подходящего существующего класса.
- Используй Laravel validation для проверки входных данных.
- Не отключай CSRF-защиту без явной необходимости.
- Не изменяй `.env` без необходимости.

## PHP

- Используй современный синтаксис PHP, совместимый с версией PHP проекта.
- Соблюдай PSR-12 и существующий стиль форматирования проекта.
- Используй строгую типизацию там, где она соответствует существующему проекту.
- Используй type hints для параметров и возвращаемых значений, если это уместно.
- Не усложняй код без необходимости.
- Предпочитай простой и читаемый код.
- Не дублируй одинаковую логику.
- Используй понятные названия переменных, методов и классов.
- Не используй сокращённые или непонятные названия переменных без необходимости.

## Blade

- Используй Blade-компоненты и существующие Blade-шаблоны проекта, если они уже применяются.
- Не помещай большой объём PHP-логики непосредственно в Blade.
- Сохраняй существующую структуру шаблонов.
- Используй `@if`, `@foreach`, `@include`, `@extends`, `@section`, `@yield` и другие стандартные Blade-конструкции.
- Не дублируй одинаковую HTML-разметку, если её можно вынести в существующий компонент.
- Не изменяй существующие Blade-шаблоны глобально без необходимости.

## CSS

- Используй обычный CSS.
- Не используй Tailwind CSS.
- Не подключай CSS-фреймворки без явной необходимости.
- Сначала проверь существующие CSS-файлы проекта.
- Не создавай глобальные стили, если изменение можно ограничить конкретным компонентом.
- Не используй `!important`, если проблему можно решить нормальной структурой CSS.
- Сохраняй существующую систему классов проекта.
- Используй понятные и последовательные названия CSS-классов.
- Не ломай существующую адаптивную вёрстку.
- Всегда учитывай desktop, tablet и mobile.
- Если пользователь просит конкретные размеры, цвета или отступы, соблюдай их.
- Не меняй дизайн существующих элементов без необходимости.

## HTML

- Используй семантическую HTML-разметку.
- Сохраняй существующую структуру страницы.
- Используй корректные `alt` для изображений.
- Не добавляй лишние обёртки без необходимости.
- Следи за корректной вложенностью элементов.
- Учитывай доступность интерфейса там, где это возможно без усложнения проекта.

## JavaScript

- Используй JavaScript только там, где он действительно нужен.
- Перед подключением новой библиотеки проверь, нет ли уже необходимой функциональности в проекте.
- Не подключай библиотеки без необходимости.
- Не переписывай существующий JavaScript, если можно внести небольшое изменение.
- Сохраняй существующую структуру JavaScript-кода.
- Учитывай работу интерфейса на мобильных устройствах.
- Не добавляй тяжёлые библиотеки ради простых эффектов, которые можно реализовать обычным JavaScript или CSS.

## Дизайн и вёрстка

- Если задача связана с дизайном или вёрсткой, сначала изучи существующую структуру проекта.
- Сохраняй существующую визуальную систему сайта.
- Не ломай уже работающие блоки.
- Учитывай адаптивность.
- Используй плавные и аккуратные анимации.
- Не добавляй чрезмерные анимации без необходимости.
- Если пользователь просит современный дизайн, ориентируйся на чистую типографику, сетку, визуальную иерархию и аккуратные интерактивные эффекты.
- Если в проекте уже используются GSAP, Swiper, AOS или другие библиотеки, сначала используй существующие зависимости вместо подключения новых.
- Не заменяй существующую библиотеку другой без необходимости.

## Изображения и ресурсы

- Перед добавлением нового изображения проверь существующую папку `public` и другие ресурсы проекта.
- Не заменяй существующие изображения без необходимости.
- Используй корректные пути к изображениям.
- Для Laravel используй существующую систему `asset()`, `Storage` и другие механизмы проекта.
- Не вставляй внешние изображения без необходимости.

## База данных

- Перед изменением базы данных сначала изучи существующие migrations и модели.
- Не изменяй существующую структуру базы данных напрямую.
- Для изменения структуры базы данных используй Laravel migrations.
- Не удаляй данные без явного указания пользователя.
- Сохраняй существующие связи Eloquent.
- Перед созданием новой таблицы проверь, нет ли уже подходящей существующей таблицы.

## Маршруты

- Перед добавлением нового маршрута проверь существующий `routes/web.php` и другие файлы маршрутов.
- Не создавай дублирующиеся маршруты.
- Используй существующие Controller-классы, если они подходят.
- Соблюдай существующую систему именования маршрутов.
- Не меняй существующие URL без необходимости.

## Безопасность

- Не отключай CSRF-защиту без необходимости.
- Не отключай authentication или authorization ради удобства разработки.
- Не добавляй секретные ключи, пароли или токены в код.
- Не записывай секретные данные в Git.
- Используй `.env` для конфиденциальных настроек.
- Валидируй пользовательский ввод.
- Используй безопасные методы работы с базой данных через Eloquent или Query Builder.
- Не используй SQL-конкатенацию с пользовательским вводом.

## Работа с ошибками

Если пользователь сообщает об ошибке:

1. Сначала определи точный текст ошибки.
2. Найди файл и строку, которая вызывает проблему.
3. Проверь связанные участки кода.
4. Определи причину.
5. Предложи минимальное исправление.
6. После исправления проверь связанные места, которые могли быть затронуты.

Не переписывай весь проект из-за одной ошибки.

## Работа с терминалом

- Перед выполнением потенциально опасных команд объясни пользователю, что они делают.
- Не удаляй файлы или каталоги без необходимости.
- Не используй команды удаления (`rm`, `rmdir`, `del` и аналогичные), если это не требуется задачей.
- Не изменяй системные настройки без необходимости.
- Не устанавливай сторонние пакеты без необходимости.
- Перед установкой новой зависимости проверь `composer.json` и существующие зависимости.

## Composer

- Перед добавлением пакета проверь, не установлен ли он уже.
- Не добавляй одинаковые зависимости повторно.
- Используй Composer для PHP-зависимостей.
- После изменения зависимостей учитывай влияние на существующий проект.

## Laravel Boost

- Если Laravel Boost уже установлен, используй его возможности и рекомендации.
- Не устанавливай Laravel Boost повторно, если он уже присутствует в проекте.
- Перед установкой Laravel Boost проверь `composer.json` и наличие соответствующих файлов.
- Если Laravel Boost ещё не установлен и его установка требуется инструкциями проекта, используй:

```bash
composer require laravel/boost --dev
php artisan boost:install
